## 🎯 작업 목적

고도화된 기업조사를 통해, 희망 기업의 채용공고가 나왔을 때 조사한 자료를 적극 활용하여 빠르게 그리고 정확히 자기소개서 및 면접 준비를 할 수 있게 함

## 📋 작업 범위

**포함 (In Scope)**

- [ ] 인재상 / 사업 내용 / 최근 이슈 조사 항목을 자유 메모(`researchNote`)에서 분리해 `Company` 전용 필드로 추가
- [ ] 위 조사 항목을 AI로 자동 조사해 채우는 기능 (**사용자 본인 API 키 + 웹 검색 도구**, 클라이언트 직접 호출)
- [ ] 사용자 Anthropic API 키 입력·삭제 UI (브라우저에만 보관)
- [ ] 조사 항목 채움률(완성도) 표시

**제외 (Out of Scope)**

- 공고 마감일 필드 추가 / 마감일 기준 정렬 / 마감 임박 알림 — **2026-08-08 폐기**. 마감일을 기업(`Company`)에 둘지 지원 건(`JobApplication`)에 둘지 결론이 나지 않아 이번 범위에서 뺀다 (기획 검수 🚫 #3). 필요해지면 별도 이슈로 다시 연다.
- 자소서 문항별 활용 메모 섹션 — **2026-08-08 제외**. 기획서 3.4 "자기소개서 관리"(공통/커스텀 질문, 버전별 500·1000자 관리)와 중복이라 그쪽으로 미룬다 (기획 검수 🚫 #2). 3.4가 아직 미구현이라 지금은 연결할 대상이 없으므로, 이번 작업은 **연결 지점만 열어두고 문항 원본은 만들지 않는다**.

## 🛠️ 접근 방식

**AI 자동 조사 — 사용자 본인 API 키로 클라이언트 직접 호출 (확정, 2026-08-08)**

> ⚠️ 이 결정은 프로젝트 기존 정책(`functions/src/llm.ts` 상단 "프론트에서 직접 호출 금지")과 **의도적으로 다릅니다.** 근거와 전제는 아래 및 "주요 결정 사항" 참조.

- **전제**: 이 서비스는 본인 + 지인 소수가 사용한다. 사용자마다 자기 Anthropic 키를 발급받아 입력하는 문턱을 감수한다.
- **왜 서버를 두지 않나**: Firebase Functions 배포에는 Blaze(종량제) 전환이 필요하고 이는 카드 등록이 필수다. 이를 피하기 위해 서버 없는 구조를 택한다.
- **왜 이 방식이 성립하나**: 번들에 들어가는 것은 **우리 키가 아니라 사용자 본인 키**다. 유출돼도 피해는 그 사용자 본인의 크레딧 한도까지이며, 다른 사용자·Firestore 데이터·계정에는 영향이 없다.
- 호출은 **SDK 없이 `fetch`로 직접** 한다. `@anthropic-ai/sdk`를 FE에 추가하지 않는다 — 키가 브라우저에 있는 구조에서 남는 위험이 공급망(의존성 오염)이므로, 런타임 의존성을 늘리지 않는 편이 낫다. (팀 규칙: 새 라이브러리 추가 전 기존 수단 우선 검토)
- **브라우저 직접 호출 허용 헤더 (✅ 2026-08-08 실측 확인)**: 요청에 `anthropic-dangerous-direct-browser-access: true`를 넣어야 한다. 헤더 없이 보내면 preflight에서 `No 'Access-Control-Allow-Origin' header`로 차단되고, 넣으면 통과한다(더미 키로 401 `invalid x-api-key` 수신 = 서버 도달 확인). **웹 검색 도구를 포함한 요청도 동일하게 통과**했다.
  - 검증 방법: Chromium(Playwright)에서 `http://localhost` origin으로 실제 `fetch` 실행. `curl`은 CORS를 강제하지 않으므로 검증 수단이 될 수 없다.
- 키 보관: `localStorage`. **컨벤션 문서는 Zustand를 말하지만 이 프로젝트 `package.json`에 Zustand가 없다** — 기존 `shared/lib/useTheme.ts`와 같은 "훅 + localStorage" 패턴을 따른다 (`shared/lib/useAiKey.ts`). Daily도 쓸 수 있도록 `shared`에 둔다.
- **AI 결과는 즉시 저장하지 않고 사용자 확인 후 반영**한다 (환각 대비 — 사용자가 검토·수정 가능한 초안으로 취급).

**보안 수칙 (강제 — 이 방식의 전제 조건)**

- **키를 Firestore에 저장하지 않는다.** 기기 간 동기화 목적이라도 금지. 우리 DB가 타인 API 키 보관소가 되는 순간 위험도가 완전히 달라진다. 키는 브라우저 밖으로 나가지 않는다.
- **AI 응답을 HTML로 렌더링하지 않는다.** `dangerouslySetInnerHTML`·마크다운→HTML 변환 금지. 현재 레포에는 `dangerouslySetInnerHTML` 사용처가 0건이며 이 상태를 유지한다 (XSS로 `localStorage` 키가 유출되는 경로 차단).
- 키를 콘솔·에러 리포트·로그에 출력하지 않는다.
- 화면 표시는 마스킹(`sk-ant-...abcd`), "키 삭제" 버튼 제공.
- 키 입력 UI에 **Anthropic 계정에 지출 한도를 설정하라는 안내**를 함께 노출한다.

**웹 검색 근거 조사 (확정 — 기획 검수 🚫 #1 결정)**

- 모델 지식만으로는 "최근 이슈"를 채울 수 없으므로, Anthropic 서버사이드 **웹 검색 도구**를 `tools`에 선언해 실제 검색 결과를 근거로 생성한다.
- 모델은 웹 검색을 지원하는 것으로 고른다. 동적 필터링이 붙은 `web_search_20260209`는 Opus 4.6 이상 / Sonnet 4.6 이상에서 지원되므로 **`claude-sonnet-5`를 기본값으로 둔다.** (Daily가 쓰는 `claude-haiku-4-5`는 미지원)
  - FE에서 직접 호출하므로 `functions/src/llm.ts`의 `MODEL` 상수와는 **무관하다.** Daily 기능에 영향을 주지 않는다.
  - 비용은 사용자 본인이 부담하므로 우리 쪽 비용 상한 문제는 없어진다. 다만 사용자에게 대략적인 조사 1회 비용을 안내하는 편이 낫다.
- 검색 범위를 좁히기 위해 도구 옵션을 활용한다: `max_uses`(호출 횟수 상한 = 비용 상한), `allowed_domains`/`blocked_domains`(채용 사이트·기업 공식 도메인 위주), `user_location`(국내 기업 우선).
- **`pause_turn` 처리 필수**: 서버사이드 도구 루프가 기본 10회에서 멈추면 `stop_reason: "pause_turn"`으로 돌아온다. assistant 응답을 그대로 이어붙여 재요청하는 루프를 추가한다 (무한 루프 방지 위해 재개 횟수 상한을 둔다).
- 응답 형식은 JSON 스키마(인재상/사업 내용/최근 이슈 + 각 항목의 **출처 URL**)로 강제한다. 도구 결과 블록이 섞여 오므로 `content`에서 text 블록만 골라내는 처리가 필요하다. (`functions/src/llm.ts`의 `parseJson`은 서버 코드라 재사용 불가 — FE에 같은 역할의 순수 함수를 `shared/lib` 또는 `entities/company/model`에 둔다)
- 웹 검색은 별도 과금 대상이다(호출 건당 요금). 사용자 부담이지만 `max_uses`로 상한을 둬서 예상치 못한 과금을 막는다.

**`Company` 스키마 확장 / 마이그레이션**

- `Company` / `CompanyInput`에 신규 필드 추가: 인재상, 사업 내용, 최근 이슈. (공고 마감일은 Out of Scope)
- 신규 필드는 전부 optional로 두어 **기존 문서 마이그레이션 없이 하위 호환**되게 한다. 기존 `researchNote` 내용은 자동 분해하지 않고 그대로 둔다(사용자가 필요 시 수동 이관).
- `hasResearch()`(조사 완료 판정)와 채움률 계산 기준에 신규 필드를 반영한다 — 기준 변경으로 기존 "조사 완료만" 필터 결과가 달라지므로 회귀 확인 필요.
- xlsx 임포트(`xlsxParse.ts` / `xlsxImport.ts`)의 "채워진 값만 병합" 규칙을 신규 필드에도 동일 적용한다 (과거 재임포트가 조사 내용을 지우던 회귀 재발 방지).

**자소서 문항 메모** — Out of Scope (기획서 3.4로 이관)

- 이번 작업에서는 문항 원본을 만들지 않는다. 저장 위치(Company 하위 배열 vs 별도 컬렉션) 결정도 3.4 구현 시로 미룬다.
- 조사 항목을 자소서 작성에 쓰는 것이 이 기능의 목적이므로, 3.4가 생겼을 때 기업 조사 화면에서 참조·연결할 수 있도록 **신규 조사 필드를 `Company` 단위로 조회 가능한 형태로만 남겨둔다** (별도 연결 코드는 3.4 이슈에서).

**서버 상태 관리**

- `useCompanies`가 TanStack Query가 아닌 `useState` + 수동 `reload()` 패턴이므로, 이번 작업은 기존 패턴을 유지한다. Query 전환은 별도 리팩터링 이슈로 분리.

## 🤔 주요 결정 사항

- **[2026-08-08] 세부 정책 4건 확정** (기획 검수 ⚠️ #4·#6·#7·#26)
  - **채움률 분모 = 조사 항목 7개**: 관심 직무·직무 설명·자격 요건·자유 메모 + 인재상·사업 내용·최근 이슈. 기업명·분류·공고 링크 같은 기본 정보는 "조사"가 아니므로 제외
  - **`hasResearch()` 기준은 기존 4개 유지**: 신규 필드를 넣으면 기존 기업이 갑자기 "조사 미완료"로 바뀌어 목록 상단 카운트와 필터 결과가 흔들린다. 완성도는 채움률로 따로 보여준다
  - **AI 결과 반영은 필드별 선택**: 미리보기에서 기존 값과 AI 결과를 나란히 보여주고 반영할 항목만 고른다. 수기로 다듬은 내용이 일괄 덮어쓰기로 날아가지 않게
  - **키 없을 때 AI 조사 버튼은 비활성화 + 안내**: 버튼은 보이되 눌리지 않고, 키가 필요하다는 안내와 설정 링크를 함께 노출

- **[2026-08-08] AI 호출 경로 — 두 번 바뀜. 최종: 사용자 본인 키 + 클라이언트 직접 호출**
  1. 최초에 클라이언트 직접 호출을 검토 → 우리 키가 번들에 노출되는 문제로 **Functions 프록시 재사용**으로 결정
  2. 이후 Firebase Functions 배포에 **Blaze(종량제) 전환 = 카드 등록**이 필수라는 제약이 확인됨. 카드 등록을 피하기로 함
  3. 대안 검토: (①) Cloudflare Workers 등 카드 없는 무료 프록시로 이전 (②) 사용자 본인 키를 브라우저에 보관 (③) AI 조사만 보류
  4. **사용 범위가 본인 + 지인 소수**로 확인되어 ②를 선택. 우리 키가 아니라 사용자 본인 키라 유출 시 피해가 본인 크레딧 한도로 한정되고, 레포에 `dangerouslySetInnerHTML`이 0건이며 런타임 의존성이 11개로 적어 XSS·공급망 표면이 작다는 점이 근거
  - **남는 위험**: 프론트 의존성이 오염되면 키를 탈취당할 수 있다(서버 프록시였다면 막혔을 경로). 이를 줄이기 위해 FE에 Anthropic SDK를 추가하지 않고 `fetch`로 호출한다
  - **재검토 조건**: 불특정 다수가 가입해 쓰는 서비스로 성격이 바뀌면 ①(무료 프록시 이전)으로 전환한다
- **[2026-08-08] 스키마 마이그레이션**: 신규 필드를 optional로 두어 기존 Firestore 문서 마이그레이션 없이 진행. `researchNote` 기존 내용은 자동 분해하지 않음.
