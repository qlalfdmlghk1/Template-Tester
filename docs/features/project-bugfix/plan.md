## 📋 작업 범위

**포함 (In Scope)**

- [ ] 지원현황 — 자소서 마감일이 없는 지원 건을 **등록 시점(오늘)이 속한 반기**로 귀속시킨다
- [ ] 지원현황 — 마감일을 나중에 입력하면 그 날짜의 반기로 **이동**시킨다 (날짜 우선, 등록 반기 고정 아님)
- [ ] 지원현황 — 지원 건 저장 직후 해당 건이 속한 반기로 **화면 선택을 옮긴다** (등록했는데 사라지는 체감 제거)
- [ ] 지원현황 — 지원 건 상세 패널을 **sticky로 고정**해, 목록 아래쪽 행을 선택해도 위로 스크롤하지 않고 볼 수 있게 한다
- [ ] 지원현황 — 상세 패널에서 **해당 기업의 조사 노트로 바로가기** 추가 (`/companies/research/{companyId}`)
- [ ] 기업 조사 — AI가 표시한 **핵심 문구를 서비스 색으로 강조**. 프롬프트에서 `**…**` 표기를 지시하고, 화면에서 그 구간만 `text-primary`로 렌더
- [ ] AI 키 — **로그아웃 시 자동 삭제(`clearAllAiKeys()`) 제거**. 키 해제는 AI 조사 설정 화면의 삭제 버튼(사용자가 명시적으로 누르는 동작)으로만 이뤄지게 한다

**제외 (Out of Scope)**

- **AI 키 기기 간 동기화** — 현행(브라우저마다 사용자가 직접 등록)을 유지한다. 서버 보관·프록시 전환 모두 채택하지 않음 (사유는 아래 주요 결정 사항 참조)

## 🛠️ 접근 방식

- **반기 귀속**: `getApplicationHalfId`가 자소서 일정이 없을 때 `UNASSIGNED_HALF_ID` 대신 `createdAt` 기준 반기를 돌려주도록 바꾼다. 저장 필드를 새로 추가하지 않고 계산으로만 처리하므로, 나중에 마감일이 입력되면 자연히 그 반기로 이동한다(날짜 우선).
  - 부수 확인: `UNASSIGNED_HALF_ID`가 더 이상 발생하지 않는지, 남긴다면 어떤 경우인지 (`collectHalfIds`의 미분류 제외 로직·`formatHalfId`의 "미분류" 라벨 정리 여부)
- **등록 후 선택 이동**: `useRecruitmentPage.submitForm` 성공 후 저장된 건의 반기로 `selectHalf`를 호출한다.
- **로그아웃 시 키 삭제 제거**: `features/auth/api/auth.api.ts`의 로그아웃 경로에서 `clearAllAiKeys()` 호출만 끊는다. 함수 자체는 남겨 두어 필요할 때 다시 붙일 수 있게 한다.

- [2026-08-12] **등록 직후 노출 보장**: 저장 후 해당 건이 속한 반기로 화면 선택을 옮긴다. 기존에는 다른 반기를 보고 있으면 방금 만든 건이 화면에서 사라졌음.
- [2026-08-12] **AI 키는 현행 유지 (브라우저별 직접 등록)**. Firestore 보관과 Functions 프록시 전환을 검토했으나 채택하지 않음.
  - Firestore 보관: 규칙(문서 ID=uid, owner-only)으로 타 사용자 접근은 막을 수 있으나, 서비스가 타인의 유료 API 자격증명을 **평문으로 보관하는 주체**가 되는 점이 부담. 운영자 콘솔 열람 가능, 규칙 실수 시 blast radius가 전체 사용자로 확대.
  - Functions 프록시: 보관 위험은 사라지지만 API 비용 부담 주체가 사용자 → 서비스로 이동.
  - 결과적으로 `shared/lib/useAiKey.ts`의 기존 보안 전제("키를 서버로 보내지 않는다")를 그대로 유지한다.
- [2026-08-12] **로그아웃 시 AI 키 자동 삭제를 제거**한다. 해제는 사용자가 AI 조사 설정 다이얼로그에서 명시적으로 누르는 삭제 버튼(`AiKeyDialog.tsx:160-168`)으로만 이뤄진다.
  - 트레이드오프를 확인한 뒤 내린 결정이다: 자동 삭제를 빼면 **공용 PC에서 로그아웃한 뒤 다음 사용자가 이전 사용자 키로 조사를 돌려 남의 계정에 과금되는 시나리오**(커밋 `6eab0e5`가 막았던 것)가 되살아난다. 개인 기기 사용을 전제로 재등록 부담을 줄이는 쪽을 택했다.
  - 참고: 설정 화면의 삭제 버튼은 **현재 선택된 제공자의 키만** 지운다. Gemini·Claude 키를 둘 다 넣어둔 경우 제공자를 바꿔가며 두 번 눌러야 한다. "모두 삭제"는 이번 범위에 넣지 않았다.
- [2026-08-12] 최초 제보의 "브라우저·기기마다 재등록" 증상은 **이 브라우저에 키를 등록한 적이 없었던 것**으로 확인됨. 배포 도메인 분리나 로그아웃 삭제가 원인이 아니었다 (`template-tester-1540c.firebaseapp.com`은 별도 배포가 아니라 Firebase Auth의 iframe origin).
