#### 1. 날짜 미입력 지원 건의 "올바른 귀속"이 정의되지 않음

- **분류**: 미정의 케이스 / 정책 모순
- **근거**:

  - `src/features/recruitment/model/useRecruitmentPage.ts:68-75` → `src/entities/job-application/api/application.api.ts:63` — 저장 payload에 `stages`가 없어 `createEmptyStages()`로 채워짐 → 자소서 일정 `null` → **모든 신규 등록 건이 예외 없이 미분류로 시작**.
  - `src/entities/job-application/model/half.ts:71-80` — 미분류는 반기 선택지로 노출하지 않는다고 **의도적 설계**로 적혀 있음("해당 건은 '전체'에서 함께 보인다").
  - `src/features/recruitment/model/useRecruitmentBoard.ts:78-83` — 기본 선택이 "현재 반기". 날짜가 있는 지원 건이 하나라도 있으면 **등록 직후 방금 만든 항목이 화면에서 사라짐**(토스트만 뜸). 지원 건이 0건인 최초 등록 때만 `halfIds`가 `["all"]`뿐이라 우연히 보임.
  - 즉 "전체에서는 보인다"는 설계 의도가 실제로는 성립하지 않습니다 — 사용자가 직접 "전체"를 고르기 전까지 새 항목은 어디에도 없습니다.
- **확인 질문**: 날짜를 하나도 입력하지 않은 지원 건은 어떻게 다뤄야 하나요? 아래 중 어느 쪽인가요, 아니면 다른 규칙인가요?
  1. "미분류" 반기 선택지를 화면에 노출한다
  2. 자소서 마감일이 없으면 **등록 시점(오늘)이 속한 반기**로 귀속시킨다
  3. 등록 폼에 자소서 마감일(또는 반기) 입력을 추가하고 **필수**로 막는다 — 폼 구조 변경 수반
  4. 미분류 건이 1건이라도 있으면 기본 선택을 "전체"로 떨어뜨린다
- **함께 정할 것**: 등록 직후 방금 만든 항목이 **반드시 보이도록** 보장할지 (예: 저장 후 해당 건이 속한 반기로 선택 이동). 위 1~4 중 무엇을 고르든 이 보장이 없으면 "등록했는데 사라진다"는 체감은 남을 수 있습니다.
- **권장 방향(참고, 사람 확인 필요)**: 등록 폼에 날짜가 없는 이상 1·4번만으로는 "새 건이 미분류로 쌓이는" 구조가 그대로 남습니다. 2번(등록 시점 반기 귀속)이 사용자가 말한 기대에 가장 가깝지만, 자소서 마감일을 나중에 입력하면 반기가 바뀌는 동작을 허용할지 함께 정해야 합니다. 정책 확정은 기획 판단입니다.

- `features/recruitment/model/useXlsxImport.ts`로 들어온 지원 건도 날짜가 비면 동일하게 미분류가 됩니다. 1번 결정이 임포트 경로에도 그대로 적용되는지 함께 확인해 두면 좋습니다. (사람 확인 필요)

#### 11. 친구 오답노트에서의 AI 생성 노출 범위
