# project-bugfix — 트러블슈팅

## 등록한 지원 건이 목록에서 사라진다 (#85)

**증상**

지원현황에서 새 지원 건을 등록하면 "추가했습니다" 토스트만 뜨고 목록에 나타나지 않는다.
"2026 상반기/하반기 어디에도 안 들어간다"는 제보로 시작했다.

**원인 — 설계 전제가 실제로는 성립하지 않았다**

세 가지가 겹쳐서 생긴 문제였다.

1. `ApplicationFormDialog`의 등록 폼에 **날짜 입력 필드가 없다.** 저장 payload에도 `stages`가 없어
   `createApplication`이 `createEmptyStages()`로 채운다 → 자소서 일정이 항상 `null`.
2. `getApplicationHalfId`는 자소서 일정이 없으면 `UNASSIGNED_HALF_ID`("미분류")를 돌려줬다.
   즉 **모든 신규 건이 예외 없이 미분류로 시작**한다.
3. `collectHalfIds`는 미분류를 선택지에서 제외하고, `useRecruitmentBoard`의 기본 선택은 "현재 반기"다.

`half.ts` 주석에는 "미분류는 선택지로 노출하지 않는다 — 해당 건은 '전체'에서 함께 보인다"고
의도적 설계로 적혀 있었다. 하지만 **사용자가 직접 "전체"를 고르기 전까지 그 건은 어디에도 보이지 않는다.**
설계가 기댄 전제("전체에서는 보인다")가 실제 사용 흐름에서 깨져 있었던 것이다.

지원 건이 하나도 없는 최초 등록에서는 `halfIds`가 `["all"]`뿐이라 "전체"로 폴백돼 우연히 보였고,
이 때문에 재현이 들쭉날쭉해 보였다.

**해결**

- `getApplicationHalfId`가 자소서 일정이 없으면 `createdAt`의 반기를 쓰도록 변경.
  반기를 문서에 저장하지 않고 매번 계산하므로, 나중에 마감일을 채우면 그 반기로 자연히 이동한다(날짜 우선).
- `createdAt`이 Invalid Date인 경우만 미분류로 남긴다 — 그대로 환산하면 `NaN-HNaN` 같은 식별자가
  반기 선택지에 섞인다.
- 저장 직후 `selectHalf(getCurrentHalfId())`로 화면 선택을 옮겨, 다른 반기를 보고 있었어도 방금 만든 건이 보이게 한다.

**배운 것**

"의도적 설계"라고 주석에 적혀 있어도, 그 설계가 기댄 전제가 실제 화면 흐름에서 성립하는지는 별개다.
이번 건은 주석만 읽으면 정상 동작으로 보였고, 등록 → 조회 흐름을 끝까지 따라가서야 드러났다.

## AI 키가 브라우저마다 사라진다? — 오진이었던 것

**제보**: "AI 등록을 브라우저마다·기기마다 다시 해야 한다."

원인을 찾는 과정에서 두 가지 가설을 세웠다가 둘 다 틀렸다.

1. **배포 도메인이 여러 개라 localStorage가 나뉜다** → 아니었다. DevTools에 보이던
   `template-tester-1540c.firebaseapp.com`은 별도 배포가 아니라 **Firebase Auth의 숨은 iframe origin**이다.
   앱 origin은 하나뿐이었다.
2. **로그아웃 시 `clearAllAiKeys()`가 지운다** → 이것도 아니었다. 실제로는 해당 브라우저에
   **키를 등록한 적이 없었다.**

결과적으로 버그가 아니었으므로 서버 보관·프록시 전환은 모두 채택하지 않았다.
다만 논의 과정에서 "로그아웃할 때마다 지워지는 건 불편하다"는 판단이 나와,
자동 삭제만 제거하고 해제는 설정 화면의 삭제 버튼으로 남겼다.

**배운 것**: localStorage가 비어 있다고 "지워진 것"으로 단정하면 안 된다.
origin 분리·미등록·삭제가 모두 같은 화면(빈 목록)으로 보인다.
